# dsh-plugins

[![CI](https://github.com/RinatITP/dsh-plugins/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/RinatITP/dsh-plugins/actions/workflows/ci.yml)

Плагины для **DeepSeek Harness (DSH)** — независимый набор под лицензией MIT,
который поддерживает Ринат Фатхутдинов. Это не официальный репозиторий DeepSeek.

## Что такое DeepSeek Harness

DeepSeek Harness — локальное рабочее пространство агента с десктопным
приложением и веб-интерфейсом. Его можно расширять устанавливаемыми плагинами:
npm-пакет поставляет патч Cordis-бандла (`dsh.bundle.patch`) для поведения на
стороне хоста и, опционально, веб-клиентскую половину (`dsh.client`), которая
встраивается в существующий интерфейс. В DSH есть официальный Plugin Manager и
CLI-команда `dsh plugin --profile <name> add <spec>` для установки таких пакетов.

## Что это за репозиторий

Небольшой монорепозиторий для плагинов DSH, которые следуют одним правилам:

- **Только официальные точки расширения.** Никакой инъекции в DOM, патчинга
  внутренностей DSH и правки файлов профиля в обход пользователя.
- **Состояние на стороне хоста.** Конфигурация сохраняется через официальный
  `configEditor`, секреты никогда не возвращаются в браузер.
- **Fail closed.** Действия, влияющие на безопасность, сохраняются выключенными и
  требуют явного подтверждения пользователя, прежде чем что-то запустится.
- **Самому репозиторию не нужны сборка и зависимости.** Чистый ESM JavaScript,
  который проверяют встроенный тест-раннер Node и валидатор без зависимостей —
  те же команды запускает CI.

## Статус

`0.1.0` — **development preview**, целевая версия DSH — **0.2.2-rc.1**.

Автоматическая проверка в этом репозитории:

- юнит-тесты в `packages/dsh-mcp-guard/test/` и
  `packages/dsh-skill-curator/test/` (встроенный `node --test`, без сторонних
  тест-фреймворков);
- `node scripts/validate.mjs` — проверяет манифест пакета, патч бандла, локали,
  иконку, наличие обязательных файлов и синтаксис JavaScript;
- workflow GitHub Actions в `.github/workflows/ci.yml`, который запускает и то и
  другое на Ubuntu с Node 22.

Механика Host и бандла **проверена** на профиле DSH Desktop `0.2.2-rc.1`:
бандл установился и активировался без перезапуска, страница `settings.section`
зарегистрирована и активна в живом реестре слотов, маршрут управления требует
заголовок намерения и допуск подписанного peer, а сквозная проверка подняла
тестовый stdio MCP-сервер через официальный `@deepseek-ai/dsh-mcp-client` и
увидела его инструмент `mcp__<name>__echo` до отката тестовой конфигурации.
Запись — [`docs/VERIFICATION.md`](docs/VERIFICATION.md).

**Остающееся ограничение:** в этой среде сборки нет управления браузером,
поэтому отрендеренная страница настроек **не** осматривалась — вёрстка, темы и
интерактивность не подтверждены, скриншотов нет. Считайте визуальный интерфейс
непроверенным, пока мейнтейнер не выполнит ручной прогон и не зафиксирует его.

## Безопасные значения по умолчанию

Это умолчания и жёсткие правила `dsh-mcp-guard` (подробности —
[`docs/SECURITY-MODEL.md`](docs/SECURITY-MODEL.md)):

- Каждый новый или изменённый MCP-сервер сохраняется **выключенным**. Включение —
  отдельное действие пользователя с предпросмотром выполняемой команды; строки с
  высоким риском дополнительно требуют явного подтверждения риска.
- Переменные окружения и HTTP-заголовки **только на запись**: API возвращает лишь
  имена ключей, но не значения; значения не попадают в ошибки, аудит и журналы.
- **Никаких выражений.** Конфигурация с loader-выражениями DSH никогда не
  записывается плагином; такие строки других плагинов остаются read-only.
- **Открытый HTTP** на не-loopback хост заблокирован, если для конкретной строки
  он явно не разрешён; URL с userinfo и инъекция в заголовки отклоняются.
- **Переменные окружения, влияющие на выполнение** (`NODE_OPTIONS`, `LD_PRELOAD`,
  `PATH`, `DYLD_*`, `DSH_*` и подобные), блокируются жёстко и не могут быть
  переопределены из интерфейса.
- **Строгий импорт**: только конверт `mcpServers`, ограниченный размер, allowlist
  полей, запрет дублирующихся ключей и prototype pollution; импортированные
  строки сохраняются выключенными.
- Мутации сериализуются, защищены ревизией и подтверждением; локальный
  HTTP-маршрут требует peer-допуска DSH и заголовка намерения, ответы не
  кэшируются.
- **Агент не может включать MCP-серверы.** Нет ни одного инструмента или команды
  агента, создающей или включающей сервер; включение — жест пользователя в
  интерфейсе настроек.

## Установка

Плагин устанавливается в **профиль** DSH из этой рабочей копии. В npm он пока не
опубликован.

### A. Plugin Manager в DSH Desktop (рекомендуется)

1. Откройте DSH Desktop и перейдите в **Plugin Manager**.
2. Установите бандл из локального каталога пакета — абсолютный путь к
   `packages/dsh-mcp-guard` в этом репозитории (официальное действие
   `install_bundle` с этим каталогом в качестве цели).
3. Перезапустите DSH, если приложение сообщит, что нужен перезапуск. Слои
   бандлов собираются при старте.

Установка из локального каталога **линкует** рабочую копию, а не копирует её,
поэтому изменения в репозитории подхватываются при следующей перезагрузке
плагина/приложения.

### B. Командная строка

```sh
dsh plugin --profile desktop add "/абсолютный/путь/к/dsh-plugins/packages/dsh-mcp-guard"
dsh plugin --profile desktop add "/абсолютный/путь/к/dsh-plugins/packages/dsh-skill-curator"
```

- Используйте тот профиль, в котором действительно работает GUI: `desktop` для
  DSH Desktop, `web` для развёртывания `dsh web`.
- Если `dsh` нет в `PATH`, документированный эквивалент —
  `npx @deepseek-ai/dsh plugin --profile <name> add <spec>`.
- Альтернативная форма для связанной рабочей копии, которую используют другие
  плагины DSH, — спецификация `link:`
  (`dsh plugin --profile desktop add "link:/абсолютный/путь/.../packages/dsh-mcp-guard"`).
- После установки/обновления/удаления полностью перезапустите DSH (не просто
  обновите страницу) — слой Host-бандла собирается при старте.

### C. Из GitHub / npm

Репозиторий опубликован по адресу <https://github.com/RinatITP/dsh-plugins>. Это
монорепозиторий, пакет плагина лежит в подкаталоге:

- **Не проверено:** установка напрямую из GitHub, в частности из подкаталога
  пакета в монорепозитории. Не считайте, что это работает.
- **Пока недоступно:** плагин не опубликован в npm. После публикации
  предполагаемый маршрут — `dsh plugin --profile <name> add dsh-mcp-guard`.

Предварительные требования, проверка после установки, удаление, обновление и
диагностика — в [`docs/INSTALL.md`](docs/INSTALL.md).

## Разработка

Для разработки ставить ничего не нужно: у репозитория нет dev-зависимостей и
стороннего runtime-кода. Плагин использует официальный
`@deepseek-ai/dsh-mcp-client` как опциональную peer-зависимость, которую
предоставляет сам хост DSH. Используйте Node.js 22 или новее.

```sh
node --test packages/dsh-mcp-guard/test/*.test.mjs   # юнит-тесты
node scripts/validate.mjs                            # валидация репозитория и хоста
node --check packages/dsh-mcp-guard/client.js        # синтаксис клиентской половины
node --check packages/dsh-mcp-guard/index.js         # синтаксис хост-половины
```

Процесс изменений — в [`CONTRIBUTING.md`](CONTRIBUTING.md), устройство плагина —
в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).
